## 문제 정의

- 핵심 고객: 요양보호사 35명 규모 시흥 방문요양센터의 센터장
- 상황: 요양보호사 이탈이 반복되고, 위험가구 민원은 카톡·전화·엑셀에 흩어져 있다.
- 고통: 문제가 한눈에 보이지 않아 사고가 터지고 나서야 알게 되고, 센터장이 매일 소방수 역할을 하며 번아웃된다.
- 문제 한 문장: 방문요양센터장은 요양보호사 이탈과 위험가구 민원이 반복되는 상황에서 센터를 안정적으로 운영하려는데, 문제가 흩어져 한눈에 보이지 않아 사고 후에야 파악하는 고통을 겪는다.

## 핵심 가치

- 흩어진 민원·이탈·위험가구 신호를 한 곳에 쌓아 사고 나기 전에 미리 볼 수 있게 하고, 근무 이력을 케어온도로 환산해 신뢰를 양쪽에 노출한다.

## MVP 기능

- 위험가구카드: 민원·고충·취소를 발생할 때마다 빠르게 기록한다.
- 케어온도 + 보호사관리: 반복 패턴과 이탈 위험 인력을 케어온도로 확인한다.
- 대체근무 요청 관리 화면: 대체근무 가능 인력을 조회하고 요청한다.

## 핵심 차별점

- 누적 기록 기반 이탈위험 자동 신호
- 민원·고충·취소가 쌓일수록 이탈 위험 알림이 올라오는 구조
- 근무 이력과 누적 기록을 케어온도로 환산해 보호사 신뢰도를 쉽게 판단하는 구조
- 일반 구인 플랫폼이나 매칭 후 종료되는 서비스가 만들기 어려운 기록 기반 기능

## 첫 사용 시나리오

- 사회복지사가 민원 전화를 끊고 해당 수급자 카드에 30초 만에 기록한다.
- 센터장이 퇴근 전 대시보드를 열어 이번 주 위험가구 2곳과 이탈 위험 보호사 1명을 확인한다.

## 가격 가설

- 방문요양센터장의 이탈·민원 반복 고통을 기록 기반으로 미리 잡아주면 월 5만~15만원을 낼 것이다.

## 이번 MVP에서 제외

- 보호자 알림
- 급여 정산 자동화
- 장기요양 청구 연동

## 협업 결정

- 팀장은 김영권이다.
- 팀장은 PR 최종 병합과 배포를 담당한다.
- MVP 역할은 센터(센터장)와 요양보호사 2개로 단순화한다.
- 사회복지사는 MVP에서 별도 로그인 역할로 나누지 않고 센터 역할 안에서 다룬다.
- AI는 요청받은 코드·문서 수정, 실행·빌드·린트 확인, 커밋, PR 생성을 수행한다.
- 파일 삭제, 대규모 이동, 의존성 추가, 공통 구조 변경은 AI가 먼저 멈추고 확인받는다.
- 공통 구조는 SPA와 역할 기반 화면 분기를 유지한다.
- 새 데이터 이름은 구현 전 `docs/data-guide.md`의 공통 이름 사전을 먼저 확인한다.
